结论
----
* claude-code-acp 0.16.2 在容器内完成 initialize（协商回 protocolVersion=1）与 session/new，
  agentInfo 来自容器内二进制；cwd 是容器路径 /workspace；configOptions 为空，authMethods
  只声明 claude-login。容器内无 macOS Keychain、宿主也没有 ANTHROPIC_API_KEY，但
  initialize/session/new 不需要凭据——docker 面的真实模型 run 属预期阻塞（不索取凭据）。
* dsh 0.1.5-rc.3 回归握手成功（configOptions model/reasoning_effort），镜像换层没有
  破坏 M3a 已验证的路径。
* codex-acp 1.13.1 的 initialize 正常，session/new 在无凭据时报
  “-32000 Authentication required”——与 M3a 记录的凭据观测点一致；本任务禁触
  ~/.codex，未注入其凭据，故这一路径以 M3a 的组件级事实与镜像内自检为准。
* 三个 agent 的容器都在 close 后按持久化名字确认不存在（confirmed_absent=True，
  docker ps -a 同名列表为空）；未做模式匹配删除。
* 脱敏: 家目录以 ~ 代替，临时目录以 $TMP/glink-acp-docker-*-<id> 代替；无凭据值。
