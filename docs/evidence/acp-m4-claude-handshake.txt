凭据与首启形态的先行实测（同一任务，真实 ~/.claude* 只读）
--------------------------------------------------------
1) Keychain 可达但内容不可用（macOS Keychain 按用户不按 HOME）
   - `security find-generic-password -a "$USER" -w -s "Claude Code-credentials"` 退出码 0，
     无交互提示：CLI 用的同一条读取命令可达。
   - 值结构（只列键名与长度，不打印值）: claudeAiOauth.accessToken 长度 0、
     refreshToken 长度 0 —— 该条目是空壳，不提供可用登录态。
   - 同一条目下本机 claude 2.1.281 `auth status` 在全新 HOME + 复制真实 settings.json
     时报 loggedIn=true / authMethod=oauth_token；把复制件里的 ANTHROPIC_AUTH_TOKEN、
     ANTHROPIC_BASE_URL 去掉后立刻变成 loggedIn=false。结论：登录态来自 settings 的
     env 块，不来自 Keychain OAuth。
2) 工作凭据形态 = settings.json 的 env 块（本机为第三方 Anthropic 兼容端点）
   - 真实 ~/.claude/settings.json 的 env 含 ANTHROPIC_AUTH_TOKEN、ANTHROPIC_BASE_URL 与
     模型/上下文相关旋钮（键名见集成笔记 §7；值不落证据）。
   - 该文件同时含约 30 条 hooks（Muxy/Otty/Orca/Herdr/harness notify）、enabledPlugins 与
     statusLine。实测把真实文件整体复制进 run HOME 时，SessionStart hook 立即在宿主上
     拉起了 ~/.harness/cli/notify.mjs，并把操作员真实的 ~/.claude/projects 等目录参数传进去
     —— 即“整体复制真实 settings.json”会把操作员的 hook 副作用带进每个 run。
3) 每 run HOME 需要的最小配置
   - 需要: 只含 env 块的一份运行期 settings → 复制到 HOME/.claude/settings.json（0600）。
     本证据用 --derive-settings-from 把它生成在临时数据根内（0600），真实文件只读
     （脚本核对 sha256 unchanged）。
   - 不需要: ~/.claude.json（CLI 在全新 HOME 首次启动时自行创建，含 firstStartTime/userID/
     GrowthBook 缓存与 .claude.json.backup.*；不依赖预先存在）。
   - 不需要: ~/.claude 下的 skills/plugins/history/daemon 等状态。
4) 驱动哪个 claude CLI
   - 适配器 0.16.2 默认驱动 @anthropic-ai/claude-agent-sdk@0.2.44 自带的
     vendor cli.js（版本 2.1.44）。
   - 同一份运行期 settings 下：2.1.44 `auth status` 报 loggedIn=false，本机
     claude 2.1.281 报 loggedIn=true。为避免把冒烟赌在 2.1.44 是否应用 settings env 上，
     冒烟按适配器官方通道设 CLAUDE_CODE_EXECUTABLE=本机 claude（2.1.281，SDK 原生二进制
     直启，实测子进程命令行确认）。
5) 首启形态
   - 全新 HOME 下 initialize + session/new 不需要任何凭据：CLI 自建 .claude.json 与
     .claude 下的 backups/debug/sessions，session/new 成功返回 sessionId 与 modes。
   - session/new 返回 modes（default/acceptEdits/plan/dontAsk/bypassPermissions）；
     configOptions 为空数组（因此 PI_GLINK_ACP_SESSION_CONFIG 对 claude-code-acp 不可用，
     缺省不配置即不触发）。
   - session/new 后立即广播 available_commands_update（本次 47 条），宿主 ACP 门禁继续
     拒绝 / 开头 prompt。

结论
----
* inproc 可用凭据形态：运行期 .claude/settings.json（env 块，CREDENTIAL_FILES 0600 复制，
  注入值并入 redactor） + CLAUDE_CODE_EXECUTABLE 指向宿主 claude CLI；
  PI_GLINK_ACP_ENV 的 ANTHROPIC_API_KEY/ANTHROPIC_AUTH_TOKEN 是等价的环境变量通道。
* Keychain 本条目的 OAuth token 为空，不能作为凭据；即使非空，macOS Keychain 也只在
  inproc 面存在（docker/e2b 无 Keychain）。
* 真实 ~/.claude* 全程只读未改（settings.json sha256 前后一致）。
