6. 为什么预装用 --legacy-peer-deps
----------------------------------
第一次候选构建用默认 npm 语义，npm 自动装入了 peer：

  /opt/pi-packages/node_modules/@earendil-works/{pi-ai,pi-coding-agent,pi-tui,pi-telemetry} 0.87.1

镜像内 pi 是 0.86.1，pi-web-access 的 `supportsDynamicTools()` 会从这份**副本**解析宿主
版本，从而把 web tools 从"eagerly available"切到动态激活路径（与产品当前行为不一致，
且扩展会从与内核不同版本的 pi-ai 副本导入）。pi 自己的 npm 托管安装正是为此关闭 peer 解析：
`dist/core/package-manager.js::getNpmInstallArgs` → `["install", …, "--prefix", installRoot,
"--legacy-peer-deps"]`（注释原文：Disable peer dependency resolution for managed installs …）。
改为 `--legacy-peer-deps` 后，/opt/pi-packages 下不再有 @earendil-works 副本，扩展回到
与 npm 运行时安装相同的 eager 回退（stderr 的提示行两者一致）。
