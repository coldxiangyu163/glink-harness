# 为什么 2026 年的 AI 编程 agent 需要 ACP 这类开放协议

**1. 消除 M×N 重复集成（LSP 式解耦）**
没有协议时，每家编辑器为每个 agent 写适配，每个 agent 又实现各编辑器 API，胶水代码随组合成倍增长。ACP 让双方各实现一次：agent 可跑在任何兼容编辑器，编辑器可接入整个 agent 生态。— [ACP 官方 Introduction](https://agentclientprotocol.com/get-started/introduction)

**2. 打破锁定，补上统一分发层**
协议把"选 agent"与"选编辑器"解耦。2026-01-28 ACP Registry 上线：agent 注册一次即可被所有 ACP 客户端安装，含 Claude Code、Codex CLI、Copilot CLI 等。— [Zed 公告](https://zed.dev/blog/acp-registry)、[ACP agents 目录](https://agentclientprotocol.com/get-started/agents)

**3. 与 MCP 分层互补**
MCP 管 agent→工具/数据；ACP 管编辑器→agent：会话、流式更新、diff 预览与改前授权。终端 agent 只需 MCP，进入编辑器则两者都要。— [CircleCI: ACP vs MCP](https://circleci.com/blog/acp-vs-mcp-whats-the-difference-for-agentic-coding/)
