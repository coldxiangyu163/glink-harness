# ACP 这类客户端-代理协议对宿主接入多种 agent 的价值

- **一次实现、多 agent 复用**：ACP 为编辑器/IDE 与编码 agent 之间定义统一协议（类比 LSP），宿主只实现一次客户端即可接入所有兼容 agent，免去为每个 agent 写定制集成，也避免开发者被单一 agent 绑定。参见 [ACP 官方 Introduction](https://agentclientprotocol.com/get-started/introduction)。
- **生态即插即用、部署灵活**：agent 只需实现 ACP 即可触达所有兼容客户端，已有 Gemini CLI、Claude Code 适配器、Goose 等加入，并同时覆盖本地（stdio/JSON-RPC）与远程（HTTP/WebSocket）场景。参见 [Zed：ACP 进展报告](https://zed.dev/blog/acp-progress-report)。

首次运行末尾打印 `parent 通过: False；child 通过: False` / `[FAIL] …`：这不是本次
live 事实的失败，而是探针**新增**的 docker inspect 快照收集有实现缺陷，两条由快照
派生的判据拿不到数据：

* 缺陷：`docker_inspect()` 的 Go template 用 `{{range .Config.Env}}…{{end}}` 拼
  JSON 数组，每个元素后都带逗号 → 数组尾逗号 → `json.loads` 抛 JSONDecodeError →
  函数返回 None，每 0.5s 重试、两轮 20s+ 全部返回 None（所以上方两轮都打印“容器
  运行期未采到 docker inspect 快照”，并让 `容器 Id 不同` 与两条挂载判据为 False）。
* 修复（本 commit）：env 名改用逐行模板单独读取、JSON 部分去掉尾逗号、inspect 失败
  记录首次原因。修复**没有**用模型重跑（授权 ≤4 轮，本次已用 2 轮）——修复后在一次性
  容器上实测同一函数：`docker run --name acp15-inspect-probe6 -e HOME=/home/acp
  pi-glink-acp-worker:latest sleep 25` 时返回有效 JSON
  （id=3581f2d44d39…、status=running、cwd=/workspace、mounts=[]、envNames=[HOME,
  PATH, NODE_VERSION, YARN_VERSION, NPM_CONFIG_UPDATE_NOTIFIER]），名字不存在时返回
  `docker inspect exit 1: Error response from daemon: No such container: …`。
