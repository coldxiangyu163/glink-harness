升级演练证据 / upgrade drill evidence
=====================================
日期: 2026-09-22
目标: 在不修改 pi 的前提下换用更高版本并重跑 smoke。

版本对照
--------
  实测基线（task-2 ~ task-7）      pi 0.86.1   （宿主全局）
  本次演练（升级后）               pi 0.87.0   （宿主全局，未做任何内核改动）
  Docker 镜像 pin                  ARG PI_VERSION=0.86.1（已实测）
  E2B 模板 pin                     同一 ARG（已实测，模板 buildId 2bec2f1d）

隔离安装验证（不动用户全局 pi 的做法）
--------------------------------------
  npm install --prefix /tmp/pi-upgrade @earendil-works/pi-coding-agent@latest
  /tmp/pi-upgrade/node_modules/.bin/pi --version   →  0.87.0

  做法说明：演练用 PI_GLINK_PI_BIN 指向隔离安装的二进制，宿主不改 PATH、不改用户全局。

结论
----
* 0.87.0 下协议分帧、事件词汇、`get_state` 身份字段、`models.json` 生成与
  `PI_CODING_AGENT_DIR` 重定向全部照旧工作，无需改动宿主或内核接入层；
* 未修改 pi 源码或包内容（仓库侧只有 `ARG PI_VERSION` 与 `PI_GLINK_PI_BIN` 两个开关）；
* Docker / E2B 的 pin 保持 0.86.1（已实测的版本）；升级到 0.87.0 只需改 ARG 并重建
  镜像/模板 + 重跑对应 smoke，步骤见 docs/pi-boundary.md §3，本次演练未执行重建。

宿主侧用法（命令的正确位置）
----------------------------
  PI_GLINK_PI_BIN=/tmp/pi-upgrade/node_modules/.bin/pi \
    LOCAL_WEB_PORT=7864 .venv/bin/python -m pi_glink.app &

  .venv/bin/python scripts/smoke-local-run.py --base-url http://127.0.0.1:7864 --prompt "…"

说明：PI_GLINK_PI_BIN 由**宿主进程**读取（config.pi_bin → build_pi_argv）；smoke 脚本只发
HTTP 请求，放在它前面不会切换宿主使用的 pi。宿主启动横幅会打印实际解析到的 pi 路径。

本次演练的实际情形：全局 pi 已被外部升级到 0.87.0，因此上文 inproc run 直接用全局 0.87.0；
隔离安装（npm --prefix）用于证明「换版本不动用户环境」的做法本身可用。
