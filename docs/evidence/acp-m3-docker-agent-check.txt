逐项结论
--------
1) 容器内 ACP 握手（两个 agent 都成功；协议版本协商回 1）
   - codex-acp（@agentclientprotocol/codex-acp 1.13.1，后继包）：initialize OK，
     agentInfo.name/version 来自容器内二进制；session/new 返回 sessionId 与 5 个
     configOptions（mode/collaboration_mode/model/reasoning_effort/fast-mode）；
     authMethods = api-key / chat-gpt。凭据就在被挂载的每 run HOME 里（~/.codex/auth.json），
     因此 session/new 不再报 “Authentication required”。
   - dsh（0.1.5-rc.3，--profile acp）：initialize OK，session/new 返回 sessionId 与
     2 个 configOptions（model/reasoning_effort）；凭据来自 ~/.dsh/.credentials.yaml。
   - 两个 agent 在 client.close() 后退出码 0；随后按容器名 force-remove 返回
     “No such container”（--rm 已回收），`docker ps -a --filter name=<name>` 为空。
   - 两个凭据源文件 sha256 前后一致（sourceUnchanged=true）。

2) 挂载契约（用同一 plan 的挂载 + 容器内 shell 验证）
   - 容器内 `echo tamper >> /home/acp/.codex/auth.json` → tamper_exit=2，
     stderr “Read-only file system”：凭据文件是嵌套只读挂载，容器改不动。
   - 容器内 `touch /home/acp/writable-check` → home_write_exit=0：HOME 本身可写，
     agent 的 sessions/cache 能落盘。
   - 容器内可读凭据（marker=readable）；宿主上被复制的凭据文件 sha256 前后一致
     （copiedUnchanged=true），容器结束后无同名容器残留。

3) 环境约束（本机实测，写入集成笔记 §5.2）
   - Colima 只把 home 树（/Users/...）共享给 VM。数据根放在 /tmp 时，绑定的文件/目录会被
     静默创建成空目录（探针第一次运行即复现：session/new 因缺少凭据返回
     “Authentication required”/“Internal error”，容器内路径是目录）。
   - 因此本机 Docker 面（pi 面与 ACP 面同规则）的数据根/工作区必须在守护进程可共享的路径
     下；本次冒烟把临时数据根放在 $HOME 下并显式记录该约束。

（证据中不含任何凭据值；smoke/握手目录随后删除。）
