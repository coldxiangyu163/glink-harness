---- report.md（宿主下载，已过 run redactor） ----
2026 年 AI 编程 agent 需要 ACP 这类开放协议，核心原因是：

1. 避免编辑器和 agent 互相锁定。ACP 让开发者“换 agent 不换编辑器”，JetBrains 也把它称为避免 vendor lock-in 的开放协议：[Zed](https://zed.dev/blog/bring-your-own-agent-to-zed)、[JetBrains](https://blog.jetbrains.com/ai/2025/10/jetbrains-zed-open-interoperability-for-ai-coding-agents-in-your-ide/)。
2. 降低集成成本。ACP 定义客户端与编码 agent 的初始化、认证、提示、流式更新、工具调用和权限流程；agent 实现一次，就可进入 Zed、JetBrains、Neovim、Emacs 等客户端生态：[Microsoft AHP/ACP guide](https://github.com/microsoft/agent-host-protocol/blob/main/docs/guide/ahp-and-acp.md)、[Zed Codex](https://zed.dev/blog/codex-is-live-in-zed)。
3. 把能力开放给用户可控的本地工作流。IDE 可展示计划、diff、终端输出，并让用户审批文件、终端和工具访问；这与 MCP 对工具/数据连接的标准化趋势一致：[JetBrains](https://blog.jetbrains.com/ai/2025/10/jetbrains-zed-open-interoperability-for-ai-coding-agents-in-your-ide/)、[MCP](https://modelcontextprotocol.io/docs/2026-07-28/getting-started/intro)。
