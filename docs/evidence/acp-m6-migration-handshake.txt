三、凭据 settings env 派生在新版是否成立（不消耗模型）
------------------------------------
派生方式与 M4 相同：只取 ~/.claude/settings.json 的 env 块写成运行期 settings
（0600，经 PI_GLINK_ACP_CREDENTIAL_FILES 复制进每 run HOME 的
.claude/settings.json）。实测派生块 11 个键（值不打印）:
ANTHROPIC_AUTH_TOKEN, ANTHROPIC_BASE_URL, ANTHROPIC_DEFAULT_FABLE_MODEL,
ANTHROPIC_DEFAULT_HAIKU_MODEL, ANTHROPIC_DEFAULT_OPUS_MODEL,
ANTHROPIC_DEFAULT_SONNET_MODEL, ANTHROPIC_MODEL,
CLAUDE_CODE_AUTO_COMPACT_WINDOW, CLAUDE_CODE_EFFORT_LEVEL,
CLAUDE_CODE_MAX_CONTEXT_TOKENS, CLAUDE_CODE_SUBAGENT_MODEL

M6 的 SDK 0.3.280 不再带 vendor cli.js，改用平台原生 cli 二进制（2.1.280）；
同一份派生 settings 放在 HOME 下的 auth 探针（旧 CLI 2.1.44 在同一探针报
loggedIn=false，M4 §7.3/§10）:

$ HOME=<derived settings> claude auth status --json   # bundled native cli 2.1.280
{
  "loggedIn": true,
  "authMethod": "oauth_token",
  "apiProvider": "firstParty",
  "analyticsDisabled": false,
  "projectsDirectory": "$TMP/m6-auth-<id>/derived/.claude/projects",
  "configDirectory": "$TMP/m6-auth-<id>/derived/.claude"
}

$ HOME=<empty> claude auth status --json
{
  "loggedIn": false,
  "authMethod": "none",
  "apiProvider": "firstParty",
  "analyticsDisabled": false,
  "projectsDirectory": "$TMP/m6-auth-<id>/empty/.claude/projects",
  "configDirectory": "$TMP/m6-auth-<id>/empty/.claude"
}

结论：原生 cli 2.1.280 认运行期 settings 的 env（派生 HOME 下 loggedIn=true，
空 HOME 下 false），因此 **settings env 派生在新版成立**，且 inproc 冒烟不再
需要 M4 的 CLAUDE_CODE_EXECUTABLE 绕行；该通道仍受支持（见六）。

七、与 M4（claude-code-acp 0.16.2）记录的逐条差异
------------------------------------
1. 包/入口/版本: @zed-industries/claude-code-acp@0.16.2（bin claude-code-acp，
   无 --version）→ @agentclientprotocol/claude-agent-acp@0.81.2（bin
   claude-agent-acp，自带 --version）。
2. 驱动 claude 的方式: SDK 0.2.44 自带 vendor cli.js（2.1.44）→ SDK 0.3.280
   平台原生二进制（2.1.280）；CLAUDE_CODE_EXECUTABLE 仍优先
   （claude-agent-acp dist/acp-agent.js 的 claudeCliPath()，M6 源码只读核对）。
3. protocolVersion: 1 → 1（不变）。
4. agentInfo: {"name":"@zed-industries/claude-code-acp","title":"Claude Code",
   "version":"0.16.2"} → {"name":"@agentclientprotocol/claude-agent-acp",
   "title":"Claude Agent","version":"0.81.2"}。
5. sessionCapabilities: fork/list/resume → additionalDirectories/close/delete/
   fork/list/resume/subagents（新增 close、delete、additionalDirectories、
   subagents）。
6. agentCapabilities 新增: _meta.claudeCode.promptQueueing=true、
   _meta.authStatus={}、auth={logout:{}}、providers={}。
7. authMethods: [claude-login]（"Run `claude /login` in the terminal"）→ []
   （登录态改由 capabilities._meta.authStatus / auth 面表达）。
8. promptCapabilities / mcpCapabilities: 与 M4 相同
   （image=true/embeddedContext=true；http=true/sse=true）。
9. session/new: M4 = sessionId + models + modes（default/acceptEdits/plan/
   dontAsk/bypassPermissions）+ configOptions [] → M6 = sessionId + modes
   （default/acceptEdits/plan/auto/bypassPermissions；dontAsk → auto）+
   configOptions [mode, model, effort]（容器/沙箱里另有第 4 项 fast）；
   M6 不再单列 models。
10. PI_GLINK_ACP_SESSION_CONFIG: M4 不适用（无 configOptions，配了会失败闭环）
    → M6 适用：mode=plan 生效（modes.currentModeId=plan 且 configOptions
    mode.currentValue=plan）。
11. 每 run HOME 落点（握手期观测）: M4 = .claude/{backups,debug,sessions,
    projects} + .claude.json + Library/Caches；M6 = .claude/{backups,sessions}
    + .claude.json（debug/projects 未在握手期创建，落点仍全在 run HOME 内）。
12. available_commands: 47 条 → 45 条（宿主门禁仍拒绝 / 开头 prompt）。
13. 权限请求的 tool kind: M4 请求不带 kind（宿主按同 toolCallId 的 tool_call
    回查，toolKindSource=tool_call）→ M6 请求自带 kind
    （冒烟实测 toolKindSource=request，见 acp-m6-migration-smoke.txt）。
14. usage_update: M4 的 141 条事件里 0 条（终态 usage=null）→ M6 冒烟每次
    run 7 条，终态落 totalTokens/contextSize/cost（basis=acp_usage_update）。
15. 重复 tool_call 通知: M4 同一 toolCallId 两条 tool_call → M6 单条
    （tool_started/tool_finished 各 2 条，无成对重复，见冒烟证据）。
16. 容器（root）与 inproc 的会话选项差异（同一 0.81.2）: 容器内 modes/
    configOptions 不含 bypassPermissions（root 下禁用），inproc 含；容器内
    configOptions 另有 fast（inproc 无）——属环境差异，各面如实记录。

八、结论
------------------------------------
* 后继包在 inproc 面完成 initialize + session/new；能力矩阵按上表逐条变化。
* 凭据形态：settings env 派生在新版成立（原生 cli 认它），且不依赖
  CLAUDE_CODE_EXECUTABLE；M4 通道仍可用。
* 真实 settings.json 全程只读（两次派生源 sha256 前后一致）；整文件不复制，
  hooks/plugins/statusLine 不进 run。
