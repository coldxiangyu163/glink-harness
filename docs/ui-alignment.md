# 前端与百鉴 UI 标准库的对齐

本仓库的前端是**无构建链的静态 ESM**（`web/` 由宿主 `host/pi_glink/static_files.py` 直接吐盘上的文件）。
它没有也不打算引入打包器，所以「和标准库长得一样、用起来一样」不能靠「引同一份组件」来保证，
只能靠**逐值抄写 + 逐值测量 + 行为自检**来保证。本文记录这份对齐的口径、事实源、交互合同、
暴露面收口、验证方式和刻意偏离。

- 事实源：`/Users/coldxiangyu/work/BR/glink-ui-library`
  - token 数值：`src/styles/globals.css`
  - 组件形态与行为：`src/components/*.tsx`（Thinking / ToolChips / ConnectionState / Tooltip / Toaster / EmptyState / Button / Badge）
  - 组合与页面几何：`src/pages/agent-assistant-demo/*`（规范站唯一的完整页面 Demo）
  - 使用规则：`百鉴 UI Design Specification.md`（§2.2 工作台布局、§2.3 两栏与栏头、§4.3 组件取用、§6 AI 体验、§8 无障碍）
- 落地：`web/styles.css`（token 层 + 组件层）、`web/index.html`（外壳骨架）、`web/modules/*.mjs`（DOM 与交互）
- 用词：`web/modules/present.mjs` 是界面上一切运行事实的唯一措辞来源（见 §5）

## 1. 对齐口径

| 层 | 判据 | 验证方式 |
|---|---|---|
| token 层 | 与标准库逐值相同 | `scripts/check-ui-tokens.py`（173 项） |
| 组件层 | 同一角色在同一视口下的计算样式逐值相同；过程列的宽度为登记偏离 | `node tests/browser/ui-parity.mjs`（30 个角色，除过程行宽度外几何 ≤1px，颜色/圆角/排版/描边/海拔逐值相等）；隔离浏览器核对过程与回答共用居中的阅读列 |
| 交互层 | 状态、开合、焦点、键盘、断点与标准库合同一致 | `node tests/browser/ui-features.mjs`（54 项） |
| 用词层 | 界面文字不暴露内核、执行面、会话与内部工具名 | `node --test tests/web/present.test.mjs` + `ui-features` 的暴露面断言 |

## 2. token 层

`web/styles.css` 的 `:root` 复制标准库 `:root` 与 `@theme inline` 的取值（L0.1 调色板 / L0.2 语义层两层结构照搬）。
脚本按块解析，不整文件扫描（标准库 `.dark` 整体重映射了语义层）。本仓库**未启用暗色**，是范围裁减不是取值不同。

**字体**：token `--font-sans-base` 与 `globals.css` 逐字相同（PingFang 优先）；标准库完整页面 Demo 在 `.baijian-demo`
作用域里把正文压成内嵌的 Noto Sans SC（`demo-font.css`，data URI，实测 400/500/700 已加载）。本仓库对齐的是 Demo
的实际渲染，所以同样只在**页面作用域**（`body { --font-page }`）换族，token 不动。
⚠ 早先这里登记过「参考页实际不是 Noto，所以按 PingFang 走」——那次测量是错的（没注意到 data URI 内嵌字体），已更正。

## 4. 断点

标准库写的是 Tailwind `max-[Npx]:`，编译为 `(width < N)`；本仓库用同一种区间写法，恰好 N 宽时两边表现一致。

| 断点 | 行为 |
|---|---|
| <1250 | 首页双列间距收紧；进度浮层 340 → 308 |
| <1050 | 侧栏 240 → 212；首页双列 → 单列；起始页留白 104 → 64；进度浮层改覆盖 |
| 主区 < 921 | 报告槽改覆盖浮层（宽 `min(620px, 100%)`），竖线与对话栏开合键隐藏 |
| <721 | 侧栏 → 64 图标条；起始页留白 → 48；栏头与输入器贴边；账号区只留 28px 头像，菜单贴栏外右侧展开 |
| <600 | 输入器工具行可换行 |

## 5. 暴露面收口（界面上不说什么）

面向读者的界面只说研究本身。以下运维 / 实现事实不再出现在界面文字里（`present.test.mjs` 与 `ui-features` 双重断言）：

| 原来暴露的 | 现在 |
|---|---|
| 产品名写成仓库名 `pi-glink`、标题「pi 内核研究工作台」、首页「把问题交给 pi…」 | 「研究工作台」；首页「今天要研究什么？」 |
| 侧栏常驻「执行面 inproc · pi 可用 · openai/gpt-5.6-sol」 | 服务正常时不显示；只在真的出问题时给一条告警（未配置 / 连不上 / 研究引擎不可用），不说内核名与执行面 |
| 运行条「pi 正在本机运行」、阶段「pi 开始处理」「本轮 agent 结束」「第 N 轮」 | 过程折叠只写动作（正在检索 / 正在思考 / 已完成 · N 个步骤）；生命周期记账不显示，只保留改变预期的阶段（整理上下文、自动重试） |
| 运行头 `session 01a0c983`、`349210 tokens`、`537.838s`、模型全名 | 会话 id 不显示；用量、用时（9 分 13 秒）、模型（去掉路由前缀）只在「进度与上下文」的运行信息里 |
| 工具行「检索 · web_search」「执行 · bash」+ `query: · queries: …` | 只写动作「检索 / 执行 / 读取网页 / 写入」+ 人话对象（查询词、命令首行、工作区相对路径、网页地址） |
| 工具输出与错误详情里的宿主绝对路径（含用户名） | 三种执行面的工作区路径统一显示为「工作区」 |
| 报告栏标题「报告 · 1ac8777fd709」、下载名 `<runId>-report.md` | `report.md` + 待核验草稿；下载名「研究报告-<标题>.md」 |
| 报错「请在 .env 填 OPENAI_API_KEY」「启动失败：HTTP 500」「事件解析失败，已跳过该帧」 | 「模型服务还没有配置…请联系管理员」「研究没能开始，请稍后重试」「有一条过程记录无法显示，已跳过」；原始错误只进失败卡的「查看详情」 |
| 恢复面中英双语、`run` / `运行` 等工程词 | 中文单语；统一叫「研究」 |

仍保留、但不属于界面文字的（开发者工具可见）：`/api/health` 返回执行面与内核可执行名、`/api/config` 返回上游 `baseUrl`、
HTTP `Server` 头带仓库名、`globalThis.__piGlink`、`pi-*` 类名与 `pi-glink-*` 本地存储键。它们属于 API / 运维面，
收口需要拆分运维端点并同步冒烟脚本，**未在本轮改动**。

## 6. 刻意偏离（登记在案）

| 项 | 偏离 | 理由 |
|---|---|---|
| 暗色主题 | 未启用 | 亮色单主题；启用需补 `.dark` 段与切换入口，属新功能 |
| 过程展开区宽度 | 行高、圆角与 ToolChips 一致；过程与回答共用居中的 720px 阅读列，窄栏按可用空间收缩 | 标准库 Demo 的固定 420px 展开容器不适合研究工具较长的查询与命令；保留 720px 上限而不铺满整个主栏 |
| 右槽内容 | 报告阅读器（Demo 右槽装文件预览/编辑器） | 同一套「右栏＝槽位」规则，装的东西随产品功能走 |
| 首页信息架构 | 标题 → 输入器 → 注脚 → 「最近研究 / 最近报告」双卡 | 取 Demo「新建对话」的起始结构 + 「Agent 首页」的双卡；条目按本项目功能 |
| 侧栏信息架构 | 研究记录直接列在侧栏，没有「会话历史」整页与「会话记录」槽 | 单一用途的研究工具，侧栏列表就是会话历史；标准库的项目 / 资料库导航本项目没有落点 |
| 输入器能力 | 只有发送 / 停止；无 @ 引用、附件、网络、创建药丸 | 本项目没有这些能力，不画没有落点的控件 |
| 对话里再发一句 | 同一研究下追加追问，而不是另起会话；「新建研究」才开启新会话 | 每轮单独落盘 run 与终帧、通过官方 `--session` 载入前一轮的会话副本；按 `parentRunId` 汇聚历史，列表只列最新一轮。会话缺失/不可信时拒绝追问，不静默创建新会话 |
| 核验 | 画「待核验草稿」徽标与说明，不画「标记为已核验」 | 没有持久化与署名主体，按钮会是一个假控件 |
| 来源 | 「进度与上下文 · 来源」列出本次检索的查询词与读过的网页（取自工具事件）；**正文不做引用角标与来源清单** | 前端不承载报告层（`tests/web/run-stream.test.mjs` 的边界断言：不解析 citation / artifact） |
| 工具失败 / 中断 | 行尾多一枚 mini 状态字（失败 / 已中断 / 已停止）；完成不写字 | 异常态需要文字而不只靠颜色（规范 §8） |

## 7. 复现

```bash
# 0) 两侧都要起服务
python3 -m http.server 5300 --bind 127.0.0.1 &        # 在标准库 dist/ 里（pnpm build:file 产物）
scripts/run-local-web.sh --port 7861 &

scripts/check-ui-tokens.py                                              # token 逐值
node --test tests/web/*.test.mjs                                        # 用词、事件模型与会话生命周期（无浏览器）
node tests/browser/ui-parity.mjs   --base-url http://127.0.0.1:7861     # 30 角色逐值（历史脚本，会写 docs/evidence）
node tests/browser/ui-features.mjs --base-url http://127.0.0.1:7861     # 54 项交互自检（同上）
node tests/browser/run-smoke.mjs   --base-url http://127.0.0.1:7861     # 真实 run 端到端（同上）
# 账号模式：隔离 fixture（临时账号库 + fake 执行面）上的人工浏览器验收，
# 详见 docs/engineering.md 的浏览器段；没有使用 npx 缓存猜版本的自动脚本。
```

⚠ 按 [工程约束](engineering.md#浏览器与-live-验收)：`ui-features` 与 `run-smoke` 会向目标服务**提交真实研究**
（前者启动后约 6 秒停止，后者跑完整一轮），三个浏览器脚本都会**覆盖 `docs/evidence/`**；运行前须确认服务归属与模型授权。

## 8. 未纳入逐值比对的部分

- **Toast / Tooltip**：标准库由 sonner / Radix Portal 运行期渲染，参考页没有稳定可测的等效节点；按组件源码的类名逐项落地，
  `ui-features` 断言 Tooltip 的圆角 / 字号 / 底色。
- **滚动条**：不参与 `getComputedStyle` 比对；宽度 8px 与「滚动时才显色」照抄组件库口径（完整页面 Demo 的侧栏滚动条常显，未跟）。
- **动效曲线**：时长与缓动取 token，未逐帧比对。
- **未登录入口与账号区**：`auth-view` / `account-area` / 邀请对话框不在 `ui-parity` 的 30 个角色里
  （参考页没有这两页）。它们是按上表逐值落地、在隔离 fixture 上人工用 ego-browser 量过几何
  （输入 36px、主按钮 40px、近黑胶囊、头像 28px），`tests/web/*.test.mjs` 断言行为；
  没有把它们写进自动逐值比对，也不声称已经过像素门禁。
