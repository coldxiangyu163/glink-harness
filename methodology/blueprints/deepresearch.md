无论题目看起来多简单，都要取证、核验并交付工作区的 `report.md`；默认工作约定（系统提示）照常适用，本蓝图的要求叠加其上。阶段是交付结构的骨架，不是执行步骤限制：检索策略与执行方法由你自行决定，但每个阶段的产出必须满足它自己的产出契约。

## 取证与引注

1. **来源分层**：优先原始来源（法条与规范性文件原文、官方公报、一手数据、官方文档）；其次是官方问答与机构口径；二手整理与转载只在前两层不可达时使用，并逐处标注该限制，不得只用二手来源支撑关键结论。
2. **一个命题对一个来源**：关键事实、数字、条款逐条紧跟它自己的可核验链接，指向具体条文或段落，不要把不同命题挂到同一个笼统链接上。
3. **区分三类内容**：已核验事实、基于事实的推断、待验证假设；后两类不得写成第一类。
4. **断言强度与证据匹配**：没有量化模型或对照结构时，不写"最优""最稳妥"这类比较性结论，改为说明证据支持的强度，并列出未比较的替代方案。

## 覆盖声明

把题目拆成可判定的问题清单，在报告中逐项声明"覆盖 / 部分 / 未涉及"；每个"部分"或"未涉及"写明原因（缺证据 / 超出范围 / 检索无果）与下一步建议。另列"重要但本报告未涉及"的事项；确认没有遗漏时，写明你检查过哪些边界。

## 自我核查

交付前完成一次独立核查：

1. 逐条把关键论断带回它的来源，确认来源确实支撑该论断，数字、条款号、主体、时间一致；
2. 实际打开关键 URL 重新核验，不能只检查链接是否可点；来源不可达时如实记录（例如返回 403），并用可访问的官方来源交叉印证；
3. 核对覆盖声明与正文一致：声称"覆盖"的子问题必须有对应正文与来源。

来源不支撑 → 降级、删除该论断或补来源；覆盖缺失 → 补检索，或写进"未涉及"。修改报告后用 `bash` 跑 `grep` / `diff` 复验旧表述消失、新表述存在。

## 「来源与核查」一节

`report.md` 末尾固定包含「来源与核查」：全部来源清单（编号 + 链接）、核查状态 `PASS` / `PASS WITH NOTES` / `BLOCKED`、核查中发现并修正的问题（没有发现时写明核查覆盖了多少条论断），以及本次没有做的检查。
